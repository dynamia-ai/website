# 审核与自行发布

普通单篇文章可由运营本人授权 Agent 完成发布，不固定要求另一人或技术人员 review。所有发布仍经过 PR；GitHub 现有保护规则优先，不以管理员绕过。

## Agent 先审核，再给出结论

完成 SKILL.md 的内容校验、lint、build 和桌面/窄屏预览，再复核整个 PR 相对最新 main 的改动，不只看本轮新增 commit：

- 对照源稿或聊天要求，检查标题、正文、图文顺序、链接和自动生成摘要；确认未改写事实、漏图、带入内部备注或误覆盖已确认内容。
- 确认仅有本篇指定语言的 Markdown 和本篇新增图片，没有网站代码、其他文章、删除、重命名或覆盖旧图。旧稿兼容范围见内容契约。
- 检查明显的型号/数字矛盾、缺乏依据的技术或商业承诺、客户信息及公开授权疑点。只列实际发现和未核实事项，不把“忠实转写”说成“事实已核实”，也不为每篇稿件编造风险或要求完整技术审计。

向运营简短说明：改了什么、摘要与预览入口、检查结果、是否可发布，以及需要决定的具体问题。没有问题就明确“未发现阻止发布的问题，无需额外技术审核”。可用独立 Agent 辅助审核，但不强制依赖某种 Agent 或额外审核人。

| 情况 | 下一步 |
| --- | --- |
| 纯内容修改，检查和预览通过，未发现未解决问题 | 运营可自行决定发布，无需另找人 review |
| 型号、性能数字、客户案例授权等存在具体疑点 | 引用问题原句及依据/缺口，由运营补充证据、改稿或决定找内容/产品/技术负责人；涉及保密或公开授权冲突先解决，不能凭“忽略风险”公开 |
| 内容格式错误、缺图或图片超限 | 在本篇内容范围内修复并复查；不能修复时保留 PR，说明缺少什么 |
| 涉及代码/样式/配置、CI 或部署构建失败、无法判断的冲突 | 暂停合并，报告具体原因并建议找技术人员；不扩大内容任务、改校验器或跳过检查 |
| 账号不能合并，或仓库仍要求其他人批准 | 提供 PR 和实际缺口，请公司仓库管理员/符合规则的审核人处理；不借用账号或关闭保护 |

业务内容疑点不一律强制找技术人员。运营补证据、修改或明确确认相关业务事实后，可继续；Agent 保留核实边界，不能伪称独立验证。新出现且未解决的问题不被先前的“检查通过直接发布”自动覆盖。

## 合并条件与操作

1. **授权**：明确“发布 / 上线 / 合并”或“检查通过直接发布”即可，由当前使用者决定；已有授权不重复索要。仅预览不创建 PR；仅改稿或提交审核则停在 PR 和审核说明。尚无发布授权时只需请运营决定是否发布，不要求转交固定维护者。
2. **最终版本**：获取最新 main 和 PR HEAD，确认目标仓库及 base 是 `dynamia-ai/website:main`。main 已前进时先同步到内容分支，不强推；无法确定内容取舍的冲突请相关人确认。重新审核最终 diff，并对最终版本完成内容校验、lint、build 与受影响预览。保存 base/head SHA，不能沿用旧 HEAD 的成功结果。有等待或再改稿时复核飞书 revision；若用户明确以当前 PR 快照为发布稿，不重新导入源稿。有新增实质改动超出原授权时再请运营确认。
3. **远端检查**：核对最终 HEAD 对应的最新检查与运行记录，`marketing-blog` 工作流的 `validate` 和当前仓库 PR 的 Vercel 构建都必须成功，即使它们尚未设为 required。其他实际 required checks 和审核要求也必须满足；pending/失败/取消/缺失不能当作通过，记录缺失时先查触发与运行状态。不要只看 `gh pr checks --required`，因为仓库可能还没设置 required。可选机器人 review 的 skipped 不代表人工批准，也不单独阻止发布。托管预览的登录墙不是构建失败，本地视觉检查即可，无需为了查看预览另行登录。
4. **合并**：无未解决问题、有权限且满足规则后，将 draft PR 标为 Ready，再执行 Squash merge。以已审核 HEAD 约束操作（例如 `gh pr merge <PR> --repo dynamia-ai/website --squash --match-head-commit <HEAD_SHA>`，或 API 的 expected head 参数）。不使用 `--admin`，不为省事关闭检查，不开启无人复核后续变更的自动合并。HEAD 变化就重新读取和复核。PR 中可保留多个修改提交，不为压成一个反复 rebase/force-push；合并时压成一个即可。
5. **回读**：确认 PR 确已 merged，记录合并 SHA；若仅进入 merge queue，仍是待合并。只报告已核实的状态，不把命令已提交写成合并成功。

## 正式上线核验

合并由现有生产流水线发布，运营不需要生产密钥或部署后台登录。查询合并 SHA 对应的生产部署，待成功后访问 `https://dynamia.ai` 的目标文章与博客列表，核对实际标题、关键改动、封面/正文图和分享图；改图时确认不是旧缓存。不能只凭 HTTP 200、预览地址或 CI 绿灯宣布上线。

确认后返回正式文章链接和简短结果。若部署失败或仍未更新，说明“已合并，尚未验证上线”及具体状态，不能编造完成时间或用预览链接冒充官网。需要技术处理时提供 PR、合并 SHA 和失败记录，不要求运营操作生产配置。撤回/删除超出普通发稿范围，由维护者创建并检查回退 PR；不 reset/force-push main。
