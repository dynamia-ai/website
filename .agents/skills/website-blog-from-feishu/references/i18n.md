# 博客多语言补译

与 `src/i18n/routing.ts` 对齐：博客每篇提交前须具备 `zh.md`、`en.md`、`de.md`。

## 何时补译

| 场景 | 行为 |
| --- | --- |
| 新增文章并要开 PR / 发布 | 源语言写完后，检查并补齐缺失的 `zh` / `en` / `de` |
| 修改文章并要开 PR / 发布 | 只改用户指定语言；**若另有语言文件缺失则补上**；已有其他语言默认不动 |
| 用户明确要求「同步改译 / 重译某语言」 | 才覆盖已有目标语言文件 |
| 仅本地预览、明确不提交 | 可不强制补译；一旦改为提交则补齐 |

禁止：为「省事」只交单语 PR；用机翻腔或不忠实扩写；把缺译留给运营手工补。

## 源语言选择

1. 用户本轮指定的源语言优先。
2. 否则：飞书/聊天原文语言；新增常见为 `zh`。
3. 补译时以该源文件（或同 slug 下最完整的源语言稿）为唯一事实来源；不要用过期另一语言稿覆盖新改动。

## 翻译标准

- **人话**：目标语言读者能自然读懂的书面语，忌生硬逐句机翻。
- **同义**：不增删事实、数字、型号、客户名、承诺与链接意图。
- **结构**：保留 Markdown 层级、列表、表格、代码块与外链 URL；图片路径按下方配图规则选择；翻译标题、正文、图 alt、`title` / `excerpt` / `linktitle` / `coverTitle` 及中文标签。
- **专有名词**：HAMi、CNCF、Kubernetes、vLLM、Dynamia、产品型号等保持通行写法；公司名按 locale：`zh` →「密瓜智能」，`en`/`de` → `Dynamia`（特殊署名按内容契约保留）。
- **Frontmatter**：`date`、`category`、`coverDisplay` 与源稿一致；`coverImage` 如存在，按配图语言规则选择对应图片；`category` 仍用英文枚举；新稿不加 `language` 字段（语言由文件名决定）。已有 `language` 的历史稿若保留则与文件名一致。
- **代码**：代码与 YAML 本体不译；面向读者的注释可译。

## 配图语言规则

逐张看实际内容，不根据文件名是否带 `-en` 判断语言。源稿图片先原样导入；完成正文补译后再确定各语言引用：

- 原图只有英文、数字、通用符号或品牌 Logo：三语共用原图，不为中文稿另制中文版，也不为英文稿重复生成英文版。
- 原图有影响理解的中文标题、标注或说明，且没有可用英文版：保留中文稿原图，为英文和德文稿制作同一张英文图。只翻译文字，保留图的事实、数字、型号、箭头、结构和视觉意义。已有合适英文图时复用，不重复生成。
- 活动现场照片、人物与合影、真实产品界面、证书、二维码等原始记录保留原图；照片中拍到中文投影也不因此重绘。若中文界面文字对理解必不可少，且没有真实英文截图或可编辑源文件，在预览中标明缺口，不伪造界面数据或二维码。
- 无法可靠保留关键数值、流程或真实信息时，不用失真的生成图替换原图；在审核说明中指出具体图片与原因。

新增英文图仅放本篇图片目录，使用新文件名，不覆盖原图。检查图片 alt 与正文语言一致，并在预览中核对三语实际显示的图片。图片与文章在同一内容 PR；修改本 Skill 的规则另开 PR，不混入文章 PR。

## 交付自检

- [ ] 本篇目录同时存在 `zh.md`、`en.md`、`de.md`
- [ ] 新补文件无大段源语言残留（专有名词与代码除外）
- [ ] 三语图片 `src` 符合配图语言规则，引用文件存在，alt 已本地化；英文图经视觉核对，且预览说明记录沿用原图与新增英文图
- [ ] 预览说明写清：源语言、本轮新补语言、未改动的已有语言
