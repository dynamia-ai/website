# 首次环境配置

仅首次配置或排障时读取。为公司同事配置企业飞书模板发稿环境；不在配置过程中提交文章、改网站功能或修改仓库保护规则。

## 检查与准备

1. **执行环境**：确认 Agent 实际所在的本机、云端或容器能读写文件、运行命令、访问 GitHub，并用浏览器或人工检查网页预览。不支持这些能力时明确缺口，不承诺所有 Agent 可用。云端不能复用本机登录态。
2. **基础工具**：检查 Git、Node.js/npm、GitHub CLI（`gh`）、官方 Lark CLI 及所需官方 Skills，缺失才安装。当前 CI 使用 Node.js 22，采用相同主版本，不擅自追随 latest 或改网站依赖。已有正常配置先复用，凭据不输出到聊天、日志、仓库或 PR。
3. **本人 GitHub 身份与权限**：检查当前登录身份，确认是同事自己的账号，能够访问 `dynamia-ai/website`，并有创建内容分支与 PR 的权限。缺登录时提供本人登录入口；缺组织邀请或访问授权时说明由谁处理，不以试推 main 验权，不借用别人的 token。
4. **仓库与启用状态**：复用正确远端的 checkout，或克隆 `https://github.com/dynamia-ai/website`。读根目录 `AGENTS.md`；保留脏改动，必要时另用干净 worktree。获取最新 `origin/main`，核对其中已具备本 Skill、`scripts/validate-marketing-blog.mjs` 以及 `coverDisplay` 字段和列表图片封面实现。不能因为本地某分支有文件就认定团队主分支已启用，也不能假设 PR #54 已合并。缺能力交维护者集成，不在发稿任务补脚本或组件；仍可继续准备账号与工具。
5. **依赖与预览**：在适合工作的干净目录用 `npm ci` 按 lockfile 安装，不升级依赖或改锁文件。运行仓库要求的基础检查并启动本地网站，实际打开已有文章的列表/详情，给出 Agent 所在环境可用的预览方式。云端端口要确认用户能访问；不能访问时明确下一步，不编造预览链接。原有构建错误记录后交维护者，不删检查绕过。
6. **企业飞书接入**：读 [Lark CLI 接入](lark-cli.md) 和官方 `lark-shared`、`lark-doc` 所需参考，使用公司批准应用和同事本人的企业飞书账号完成最小权限授权。从用户提供或当前上下文已有的企业《官网博客发布》SOP 链接进入，读取其中的模板母版和官网文章库链接；确实没有入口时只集中索要这一个 SOP 链接，不让用户拆填多个 URL，不猜 Wiki token 或采用任意同名模板。实际验证正式模板、稿件副本及其中图片可读取；未提供可测稿件或图片时明确标为待验证，不能只凭登录成功宣布完整环境就绪。完成配置后的日常局部聊天改稿无需再次读飞书或重填模板。

需要本人登录、组织邀请或管理员批准时，只暂停依赖它的操作，继续其他独立检查。不要索取密码、App Secret 或 token；不能自动完成的动作要提供清楚的入口和责任人。

## 配置结果

简短报告：哪些已就绪；哪些缺失或未验证；同事本人/管理员必须做什么。区分“工具已安装”“主分支流程已启用”“企业模板/稿件/图片可读”“预览可用”，不要将部分准备完成写成可发稿。配置任务结束后，日常使用回到 Skill 的新增或修改入口。
