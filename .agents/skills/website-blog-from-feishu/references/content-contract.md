# 网站博客内容契约

依据 `src/lib/blog-server.ts`、`src/types/blog.ts` 和现有文章。网站内容机制变更时同步本契约。

## 新增：公司飞书模板稿件

仅供公司同事使用。新增必须来自企业飞书中正式模板的副本；模板入口以企业内《官网博客发布》SOP 为准，不接收任意外部文档作为新增稿，不将企业内部链接写进公开仓库。首次配置核验母版和官网文章库，日常核对稿件属于本企业且结构符合模板；来源不明时先确认，不能仅凭文章标题认定为正式稿件。

文档名称作为 `title`，必须是实际文章标题，不能发布模板名或“副本”。读取预填的作者行、可选封面，以及唯一“正文”标题之后直至文档末尾的全部内容；正文不能为空。新模板不设摘要字段，作者行缺失也可默认，不向市场追问。模板提示不进入文章或作者值；“正文”之后都视为可发布正文，不在那里夹放内部备注或操作指令。

保留作者措辞、段落与图文顺序、链接、图注及标题层级，只做网站格式转换，不自动润色、扩写、翻译或补充事实。飞书的字体、颜色和分页不保证逐像素复刻。若存在旧模板成对的“正文开始”和“正文结束”，只取该区间并使用旧模板的文章标题等字段，忽略其后内部备注。旧边界不成对、重复，或同时出现两种正文结构时，先确认边界，不能拼接两种解析结果。

Agent 处理其余字段并随预览展示，无需逐项请求确认：

- `author`：模板预填“密瓜智能”。作者行是默认公司名“密瓜智能”或“Dynamia”时，按目标 locale 使用中文“密瓜智能”、英文“Dynamia”；字段缺失也采用此默认值。用户修改的特殊署名、稿件或旧模板中的真实明确署名、聊天明确要求保留的公司写法优先原样使用，不把转载原作者改成公司。作者值不包含模板提示，预览说明列出实际值并告知当前正文页面不展示署名；这仍是网站必需元数据，不要求市场额外填写。
- `excerpt`：由 Agent 从正文忠实生成 1–2 句摘要，不添加原文没有的事实或主张。预览时显眼列出摘要并提示市场检查，按聊天反馈直接局部调整，不要求填写摘要或额外确认表单。兼容旧版公司模板中的摘要或用户明确提供的摘要，按用户指示使用；这不是新模板的输入要求。
- locale：优先用户指定，否则依据单一原文语言判断 zh/en；混合而目标不明时询问。德文需维护者先扩展页面。
- `date`：新稿默认处理当天的 Asia/Shanghai 日期；用户指定日期则用指定值。日期只用于展示，不预约上线。
- `category`：从 `dictionary/en.json`、`dictionary/zh.json` 的 `blogUI.categories` 共有键选择最贴切项，不新建分类。
- `tags`：从原文主题或名称提取，不能添加无关标签。
- slug：生成英文小写、数字和连字符形式，检查文章路径及已有 PR，不覆盖已有文章；`hello-world` 为隐藏示例，不作为投稿目标。
- 封面：封面区域有一张图时使用图片封面；空白用网站文字封面。不把首张正文图擅自当作封面。多张且用途不明才询问。

## 路径与字段

文章：`src/content/blog/<slug>/<locale>.md`；新图片：`public/images/blog/<slug>/<filename>`。博客正文放 Markdown，不写进 UI 字典。新文章示例（只展示结构，不可原样发布）：

```yaml
---
title: '对外文章标题'
date: '2026-10-08'
excerpt: '根据文章正文提取的摘要。'
author: '密瓜智能'
tags:
  - HAMi
category: 'Company News'
coverDisplay: 'image'
coverImage: '/images/blog/example-post/cover.jpg'
---
```

`title/date/excerpt/author/category/tags` 非空，日期为真实有效的 `YYYY-MM-DD` 字符串。新稿不加 `language`，语言由文件名决定。`linktitle`、`coverTitle` 为可选独立标题；没有需求不填。`title` 是文章标题，`coverTitle` 是文字封面标题，`linktitle` 是短标题；修改其中一个不隐含修改其余两个，需结合实际预览说明差异。

`author` 当前用于文章数据、Article 结构化数据和 Open Graph 作者信息，正文页尚不展示署名。不承诺读者能在页面看到，也不擅自把署名插入正文或修改组件；原文已有署名照常保留。

图片封面写 `coverDisplay: image` 和 `coverImage`。新稿封面区域无图写 `coverDisplay: text` 并省略 `coverImage`；可按用户要求写 `coverTitle`。这控制列表卡片：分享图仍按网站现有逻辑优先使用有效 `coverImage`，否则尝试首张本地正文图；分享平台还有自己的裁切规则，预览中分别说明，不能承诺空封面时分享图也是文字封面。详情页没有新增独立头图。封面文字排版、颜色和字号属于网站组件，不在发稿范围。

列表封面容器固定为 **16:9**，图片以 `object-cover` 居中裁切，悬停时约放大至 1.05 倍，右上角还有分类标签。建议准备 **1600×900** 的 JPG/PNG/WebP，尽量控制在 **2 MiB** 内以改善加载；像素尺寸和建议体积不是代码硬门槛，不添加新的拒绝规则。关键文字、Logo 和人物不要贴边，并避开右上标签区域。

Agent 读取真实像素宽高与比例，检查桌面、窄屏和悬停状态下的裁切与清晰度。非 16:9 图片仍可使用，不能只因比例不同就拒绝；不拉伸图片或通过放大小图伪造清晰度。出现关键内容被裁掉、遮挡或明显模糊时，集中请用户换图或给出裁切方案，未经同意不改变图片内容。

读取器没有 `draft/published/scheduledAt` 通用过滤；不要写这些无效字段。待审稿留在未合并分支。

## 修改：当前文章加聊天要求

从用户给定官网 URL 解析 slug/locale，读取仓库当前文章；已有同篇待审 PR 时，以其当前内容开始并保留先前修改。只修改自然语言要求能唯一定位的字段、句子、段落或图片；有多个匹配或目标不明才询问。保留文章 URL、其他语言和未指定字段，不全篇重导入、格式化或全局替换。

- 改文章标题默认只改 `title`。已有 `coverTitle` 或 `linktitle` 时保留，在预览中指出；确需一起调整但用户意图不明时一次问清。
- 修改摘要的聊天反馈只更新 `excerpt`；未要求修改摘要时保留原值，不因为改了标题、正文或图片就重新生成。
- 已有文章未明确要求修改作者时原样保留 `author`，不套用新稿的默认署名。
- 换封面只更新封面相关字段和新素材；换正文图只更新指定正文图片及必要的替代文本、图注，不动封面。
- 直接使用用户聊天上传的图片或可访问的本地文件，先检查格式和内容。无需让用户先编辑飞书。
- 沿用已有 slug；原样保留历史 `language` 标记（须与文件名匹配）和基线已有的跨目录本地栅格图片引用，不借改一句话迁移全文。兼容不允许新增/改变 `language`、新增跨目录图片引用，或增加旧共享图的引用次数；新图片只能放当前文章目录。
- 未指定的 `coverDisplay`、`coverImage` 和封面标题保持原值，避免历史文字封面意外切换为图片。其他旧内容若不能通过校验，报告具体冲突，不擅自扩大改稿范围。

以后再收到飞书源稿，仍须与当前文章比较，只应用明确要求的变化；旧源稿不能抹掉聊天修改。用户明确要求整篇重写时才替换整篇，并列出内容差异。不自动回写飞书，不要求人工同步两份文档。

## 正文与图片约束

- 支持段落、粗体、斜体、列表、引用、代码块、公开 HTTPS 链接、站内绝对路径、简单 GFM 表格、本地图片与图注。正文标题从 H2 起，保持原有相对层级，页面负责展示文章标题。
- 不允许原始 HTML（含 HTML 注释）、JSX/MDX、脚本、iframe 或可执行协议链接。代码块内的 HTML 示例仍可保留。
- 合并单元格、飞书多维表格/电子表格、音视频、嵌套卡片、画板、同步块和一般附件无法直接转成普通 Markdown。报告具体内容并提供纯文本、简单表格或插图方案，未经授权不省略实质内容，不改造网站。
- 飞书图片用官方 Lark CLI 下载；聊天附件或本地图片直接验证使用。仅有不可下载的临时外链时，请用户上传图片或插入飞书；不任意抓取外链。每张正文图需要有意义的非空替代文本。
- **图注映射**：当前 `src/lib/rehype-image-captions.ts` 会把 Markdown 图片的非空 alt 自动显示为带编号的图注。飞书图片已有 caption 时，用原图注文字作为 alt，不再另外生成图注段落；只清理首尾空白，以及与本篇正文当前图序一致的“图 N：/Figure N:”编号前缀，由网站补一次编号。编号乱序或正文按旧编号引用时先核对，不能静默重编号。没有 caption 时才根据图片生成简洁、客观的 alt。飞书原本独立的说明段落仍保留，不能把它当成转换器多出的图注删除。预览时逐张确认图注没有重复、遗漏或改变含义。
- 新图片使用本篇目录下新文件名，不覆盖旧素材，不引入 SVG、HTML、可执行文件或 symlink。单图最多 10 MiB，全篇引用图片合计最多 40 MiB；必要时保真压缩并检查清晰度，无法满足则报告，不改检查器。

## 授权与记录

明确的发稿或官网改稿请求授权将指定内容提交审核；无需模板勾选。只要求预览时不提交公开 PR。来源含内部、未公开标记或与用户要求冲突时集中确认。

纯聊天修改在 PR 记录 `source: chat`、目标 slug/locale、基线 SHA、修改摘要及检查结果，不虚构飞书 revision。使用飞书时另记录文档 ID 的 SHA-256、revision 和读取时间；内部 URL、原文快照、评论和未引用附件不提交到公开仓库。两条路径都只交付待审 PR，审核合并和实际上线需分别确认。
