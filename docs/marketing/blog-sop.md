# 市场同事：用飞书和 Agent 更新官网博客

你负责写稿、选封面、确认对外内容。Agent 负责把稿件转换成网站格式、处理图片和创建待审核版本；网站维护者审核后发布。

## 首次使用：准备账号和工具

1. 自己的 GitHub 账号，由公司邀请加入 `dynamia-ai/website`。需要能创建内容分支和 PR，但不需要管理员权限或生产部署密钥。公司应限制 main 直接写入与绕过审核。
2. 你熟悉、公司允许使用的 Agent 工具及所需账号。它需要能读写项目文件、运行命令、调用 Lark CLI 和 Git，并提供浏览器预览或人工检查入口；只有聊天能力的工具不能独立完成这套流程。
3. 自己的飞书账号，可以阅读稿件及其图片，并完成公司批准的 CLI 应用授权。

GitHub 登录、飞书登录和组织邀请需要你本人确认。工具安装、拉取仓库、检查环境和启动预览都可交给 Agent。不要把密码或 token 发给 Agent。

打开你熟悉的 Agent 后，把这段话交给它：

> 请帮我配置 Dynamia 官网博客编辑环境。仓库是 https://github.com/dynamia-ai/website 。克隆仓库并将该目录设为当前工作项目，读取 AGENTS.md、docs/marketing/blog-sop.md 和 .agents/skills/website-blog-from-feishu/SKILL.md。检查 Git、GitHub CLI、网站依赖及飞书官方 @larksuite/cli，安装所需官方 Lark Skills，复用已配置的公司应用；只申请读取稿件和图片所需权限。需要我登录时给我登录入口。最后验证能读取我提供的飞书文档并启动本地网站。不要发布文章或修改官网功能。

Skill 随仓库分发，团队只维护一份。`.agents/skills/` 是本仓库的存放位置，不代表所有 Agent 都会自动发现它。支持 Skill 自动发现的工具，可以按其界面加载 `website-blog-from-feishu`；其他工具直接使用下面的完整路径指令，不依赖特定的 `$` 或 `/` 调用语法。不要从网上安装不明来源的同名 Skill。

如果 Agent 在云端或容器运行，Lark CLI、GitHub 登录和仓库文件必须在它实际执行命令的环境里可用，本机已登录不等于云端已登录。不会自动读取仓库规则的工具，也必须按指令先读 AGENTS.md。

## 每次发稿：四步

1. 向维护者取得团队飞书模板链接，点击飞书“创建副本”。仓库中另存有 [模板内容](feishu-blog-template.md)，可以对照补齐。
2. 填标题、摘要、作者、日期、语言、分类和标签；选择上传图片封面或网站文字封面。图片封面请插在模板“封面”章节，不要只设置飞书文档最顶部的装饰封面。正文写在两个边界标题之间；内部讨论放“内部备注”。
3. 确认文章、图片、客户名称和数据可以公开，然后把下面这段话和文档链接交给 Agent。
4. 打开 Agent 给出的预览，检查标题、封面裁切、段落、表格、链接和手机布局。满意后请维护者审核发布。

> 请先读取仓库 AGENTS.md，再读取并遵循 .agents/skills/website-blog-from-feishu/SKILL.md，把这篇飞书文档的最新版本生成官网博客：[文档链接]。请完成图片处理、检查和预览，创建待审核 PR，不要合并上线。

“PR”就是一次有记录的修改申请。创建 PR 不代表已经上线；飞书里的“展示日期”也不能用来预约上线。

## 修改已经发布的文章

继续编辑原飞书稿件，提供原文章网址：

> 请先读取仓库 AGENTS.md，再读取并遵循 .agents/skills/website-blog-from-feishu/SKILL.md，用这篇飞书文档的最新版本更新已有博客：[飞书链接]。原官网文章：[官网网址]。本次主要修改：[说明]。保留原网址，生成预览和待审核 PR。

当前支持中文和英文独立稿件，德文博客需要维护者先扩展页面。只给中文稿就只更新中文；需要翻译时明确提出，并由对应负责人审核译文。

## 完成状态怎么看

| Agent 返回的状态 | 代表什么 |
| --- | --- |
| 本地草稿 | 仍有缺字段、缺图或检查未通过；还未发起正式审核 |
| 待审核 PR | 修改已上传到工作分支，等待审核；不是生产发布 |
| 预览可用 | 可以查看效果，预览可能公开，素材应已获公开许可 |
| 已合并 | 维护者接受修改，仍需检查生产部署是否成功 |
| 已上线并验证 | 生产页面可访问，内容、图片、列表已核验 |

看不到飞书文档：确认当前飞书账号有权访问文档和图片；管理员限制应找管理员。图片缺失：直接将原图片插入文档，不只粘贴临时链接。检查失败：让 Agent 报告具体原因并保留稿件，交维护者处理。不要让它删除检查、改官网代码或直接覆盖 main。

## 发布与撤回

网站维护者检查 PR 和预览，确认后合并，并检查真实生产部署及官网链接。如需撤回，请维护者创建回退 PR；不要直接删除仓库文件。搜索索引是否需要单独刷新，由维护者按现有部署配置处理。

本流程不支持定时发布、自定义页面布局、任意附件上传或插入交互代码；这些需求交给网站维护者。
