# 维护者：博客编辑流程落地与验收

## 使用方式

本流程供公司同事使用，Agent 品牌不限。新增必须使用企业 SOP 提供的正式飞书模板副本：市场写标题、正文和可选封面，文档名称为标题，“正文”之后都是待发布内容。模板作者预填“密瓜智能”，特殊署名可修改该行；Agent 将默认公司名按语言取中文“密瓜智能”、英文“Dynamia”，保留特殊署名、转载真实署名和聊天明确指定的公司写法。作者仍是非空元数据，当前正文页不展示，交付列出实际值；字段缺失可默认，不追问。模板不设摘要字段，由 Agent 从正文忠实生成 1–2 句，不添加事实，与日期、语言、分类、标签和 slug 一起处理。预览时显眼列出摘要，聊天反馈可直接调整 `excerpt`，无需额外表单。旧版公司模板的署名、摘要和成对正文边界仍兼容，不能混读。

首次配置必须完成官方 Lark CLI、公司批准应用、本人企业飞书授权及模板/稿件/图片读取验证。配置就绪后，修改用官网 URL 加聊天自然语言要求，图片可直接上传或提供可访问本地文件，不必每次重读飞书或重填模板。只改指定位置，不全篇重导入。聊天改后以仓库/当前待审分支为准，不自动回写飞书，也不要求市场回填；以后收到旧稿仍以局部修改为默认，整篇重写须用户明确提出。

发稿或官网改稿请求包含将指定内容提交审核的授权，模板不增加公开确认表单；仅预览不提交公开 PR，遇内部/未公开标记冲突时集中确认。默认交付预览、内容审核说明和 draft PR。公司同事使用本人的 Write 权限，在明确授权发布、上线、合并或“检查通过直接发布”后，可由 Agent 完成单篇内容 PR 的合并与上线验证，无需固定技术人员审核；已有授权不重复确认。仅提交审核或暂不上线的要求优先，不能自行扩大授权范围。回退仍由维护者处理。

Agent 合并前须对照源稿和本次要求核查 diff、元数据、图片与桌面/窄屏预览，报告具体发现；没有发现问题就如实说明，不附加泛泛警告。业务事实或客户公开授权不明确，由运营补充依据、确认或决定请业务负责人复核；代码越界、技术检查失败、冲突无法确认或权限不足交技术同事处理。检查通过后，在 PR 最终 head 上核实远端必需检查及部署构建、满足现有保护规则，再转为 Ready 并 Squash merge。无需托管预览登录，但远端构建失败不能用本地成功替代。合并后等待生产部署并验证正式页面、图片和链接，不把合并成功写成上线成功。

## 一次性启用

1. 核对最新主分支和建设 PR 的状态，先集成最新 main，再审核合并 Skill、校验器、所需封面支持及文档。不要假设 PR #54 已合并。市场 Agent 配置时必须确认主分支已有入口和校验器；缺失则联系维护者，不自行补写或从未知分支安装。
2. 由管理员配置 main ruleset/branch protection：要求通过 PR 合并、禁止强推/删除、限制绕过者；市场可获 Write 权限，不授予管理/绕过权限。纯单篇内容 PR 不额外强制技术人员审核，避免用全仓至少一人审批的规则阻断运营自助发布。已有规则调整前仍须遵守，不能以本指南为由跳过；Skill 不负责修改规则。
3. 工作流实际运行后，将 `marketing-blog / validate` 及实际 CI/部署构建检查设为 required check，名称以 GitHub 展示为准。提交 workflow 文件本身不启用强制规则；无需把登录托管预览作为人工发布门槛。
4. 建议由管理员用真实维护团队为 `.github/`、`.agents/`、`scripts/`、`package*.json`、`AGENTS.md` 和应用代码设置 CODEOWNERS，并配置与这些代码路径相匹配的审核规则；实际验证纯内容 PR 无需额外人工审批、代码变更必须由维护者审核。不要假定写入 CODEOWNERS 就已启用强制规则。普通 Write 权限没有“只能写博客目录”的隔离；Skill、校验和审核不能被描述为权限沙箱。
5. 核对 main 到生产的关联、PR 预览及其公开性、构建变量和 Algolia 刷新方式。市场无需生产密钥，发稿 Skill 不直接写线上搜索索引。
6. 批准官方 Lark CLI 应用和所需只读权限，要求每位公司同事用本人企业飞书账号完成首次授权并验证模板、稿件和图片读取。凭据留在 Agent 实际执行环境，不放 GitHub Actions；日常局部聊天改稿不要求重复授权。
7. 在团队知识库维护一个入口和模板母版，文章副本放固定的官网文章目录。市场无需填写发布信息表、维护发布台账或回填飞书。内部链接只放公司知识库，不放公开仓库；按实际团队权限配置模板访问。

## 校验边界

Skill 规定单篇、局部修改、预览和经授权的 PR 发布。校验器/CI 检查范围、删除/重命名/软链接、字段、日期、原始 HTML/不安全链接、图片路径/真实签名和体积。它不证明内容与原文一致、事实正确或视觉质量，也不替代网站的运行时安全治理。Agent 的内容审核与实际页面检查仍须完成；发现业务问题由运营决定处理，技术问题由维护者处理。

历史稿局部修改允许原样保留与文件名一致的 `language` 及基线已有跨目录本地栅格图片引用；不允许新增或改变该字段、扩大旧共享图引用，或新增跨目录图片。新图片仍进本篇目录，不能覆写旧图。其余校验失败应明确报告，不借微调标题迁移全文或绕过检查。

## Agent 适配

以 SKILL.md 和所需参考为流程来源，支持自动发现或显式路径读取，不为每个品牌复制规则。`agents/openai.yaml` 可忽略。验证实际环境能读写仓库、运行 Git 和官方 Lark CLI、读取企业模板与稿件图片并完成预览。尚未在其他 Agent 上完成实跑，不能将品牌中立的文档等同于全客户端兼容性认证。

## 场景验收

- 从没有配置的新 Agent 开始，检查流程已在主分支启用，完成本人 GitHub/企业飞书登录、公司应用配置，并实读正式模板、稿件副本及图片；配置完成后的聊天改稿不重复读取飞书或授权。
- 用公司正式模板的副本填写真实标题和图文正文完成新增；默认公司作者按中英文选择，特殊署名、转载原作者和明确保留写法不被覆盖，作者行缺失不追问。自动生成忠实摘要，封面为空使用文字封面，不追问摘要/日期/分类/标签/slug。摘要在预览中明确呈现，聊天反馈只修改 `excerpt`，不影响其他内容。
- 用真实封面及正文图验证下载、图文顺序、预览和 draft PR；同时验证旧模板边界不会混读或带入内部备注。
- 官网 URL 加“将某句改成某句”：只产生该处修改，保留其他语言、日期、作者、摘要、分类、标签、历史封面和共享图片。
- 改 title 时不偷偷改 coverTitle/linktitle；聊天附件换封面、换一张正文图分别只影响目标位置，新素材不覆盖旧文件。
- 复用同篇未合并 PR，保留既有修改；旧飞书稿不能覆盖聊天修改。整篇重写只有明确要求才执行，并列出变化。
- 仅预览不创建公开 PR；内部标记冲突、缺图、无权限或目标歧义时集中说明，保留草稿；飞书读取时检查 revision 变化，聊天来源不得编造 revision。
- 普通发稿交付预览、内容审核说明和 draft PR；只提交审核时不合并。明确授权“检查通过直接发布”后不重复索取发布许可，检查 PR 最终 head 和现有规则后转 Ready、Squash merge，再验证正式官网。新提交出现时重新核对受影响内容并等待新版本检查，不能复用旧 head 的通过结果。
- 内容审核指出具体事实、图片或公开授权疑点，由运营补证据、确认或决定找业务负责人；无发现时不制造泛泛警告。技术检查或部署构建失败、代码越界、无法确认的冲突、权限不足时停止合并并交技术处理。不把托管预览登录页当作构建失败，也不因本地通过而忽略真实远端失败。
- 校验拒绝首页/其他文章修改、script/iframe、远端图片、非法日期、删除文件及新增跨目录引用。通过后用正式文章验证真实发布和回退，不合并测试稿。
